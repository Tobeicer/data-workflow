# 微信商品信息分析-提取-存储规划 v1.0

日期：2026-08-11　状态：待评审　唯一入口：`adapters/wechat/README.md` → 本文件

## 1. 目标与定位

把微信（群聊 + 朋友圈）中的**商品相关信息**转化为结构化商品数据，与七大商品来源（1688/淘宝/京东/拼多多/抖音/闲鱼/漫立方）的 L2 商品资产比对、补充，形成"行业情报 → 商品数据"链路。

微信产出定位：**商品情报/线索**（报价、货源、需求、渠道、图片证据），不替代主数据来源。

## 2. 信息形态分类（4 类 + 判定规则）

| 形态 | 描述 | 判定规则 | 典型内容 |
|---|---|---|---|
| A 纯文字 | 仅文本，无图片无链接 | `type_name=text` 且无 URL | "出一台娃娃机5000元，广州自提" |
| B 纯图片 | 仅图片（单张或多张） | `type_name=image`（含视频缩略） | 实机照片、参数铭牌、报价单、多台设备合影 |
| C 链接 | 含商品/页面链接 | 文本含 URL | 淘宝/京东/拼多多/小程序/公众号文章链接 |
| D 混合 | 文字+图片/链接组合 | 同时命中 ≥2 类 | "看图，这台推币机 3 万" + 图片 |

**判定优先级**：有 URL → 形态 C/D；无 URL 有图 → B/D；仅文字 → A。每条消息产出一个形态标签，写入 `wechat_msg.signal_form`（扩展字段）。

## 3. 管道总览

```text
微信本地库（只读）
  → L1 采集+入库（collector --load，已有）
  → 形态分拣（form_detect：A/B/C/D + 群权重）
  → L1 预筛（product_signal，已有，按群权重加权）
  → L2 形态专项提取
      ├─ 文字：规则初提 + AI 结构化
      ├─ 图片：本地图片定位 → 解密/下载 → OCR → AI 结构化
      ├─ 链接：域名分类 → 商品 ID → 详情抓取（复用已有 adapter）→ 结构化
      └─ 混合：多模态合并 → AI 结构化
  → L3 校验去重（同源/跨源）
  → 存储（wechat_product_* 系列表）
  → 比对交付（与 L2 商品比对 → 情报报表/线索推送）
```

控制面：n8n 工作流（已有）扩展为：采集 → 预筛 → 形态分拣 → 专项提取 → AI 结构化 → 入库 → 通知。

## 4. 各形态详细方案

### 4.1 形态 A：纯文字

**步骤 1 规则初提**（`extract_text.py`，成本≈0）：
- 价格：`PRICE_RE`（¥/元/块/万/w/k + 数字，范围如 "3-5万"）；单位归一化（万→×10000，k→×1000）
- 设备名：`product_keywords.json` 强词命中 + 邻近词扩展（"推币机/推币综合/礼品机"）
- 数量："X台/组/套/个" 正则
- 新旧："全新/九成新/二手/翻新/库存/清货" 词表
- 意向：出售/求购/转让/回收/招商 词表 → `intent`
- 联系方式：手机号（`1[3-9]\d{9}`）、微信号、@人名
- 地域：广州/番禺/全国 等（可选）

**步骤 2 AI 结构化**（`ai_classify.py` 扩展）：对规则初提结果做语义确认 + 补全，输出统一 JSON（见 §5.2 schema）。规则与 AI 双轨：规则给出强证据字段，AI 补全弱字段，冲突时标记 `field_conflict` 走人工。

### 4.2 形态 B：图片（重点难点）

图片消息内容在 `message/media_0.db`（TimeStamp/Name2Id/VoiceInfo）与 `D:\xwechat_files\<账号>\msg\attach\` 目录。链路：

1. **图片定位与解密（H3 已实现）**：`img_decrypt.py` 用 kvcomm `uin` + 数据目录 `wxid` 推导 AES key（`md5(uin+wxid)` hex 前 16 字符，XOR=uin&0xFF），解密 V2 `.dat` 为 JPEG；`packed_info_data` 关联消息→图片，结果落 `staging.wechat_img`（`(chat, local_id)` 唯一、`dec_ok` 标记损坏）
2. **图片读取**：解密后的 JPEG 存 `runtime/tmp/wechat/img_dec/`（gitignored），路径映射写入 staging
3. **OCR 文本提取（H4 候选）**：多引擎方案
   - 首选：微信自带 OCR（不引入依赖）或本地 PaddleOCR/RapidOCR（离线、免费）
   - 备选：API OCR（中转站多模态模型直接读图）
4. **AI 结构化（多模态，H3 已实现）**：`ai_classify.py --images` 把图片交给多模态模型，输出：
   - 单台：设备名/型号/规格/价格/新旧
   - **多台实机枚举**与**铭牌/参数表结构化**为 H4 增强项
5. 图片证据：保存原图引用（`image_path`），供人工核验与后续复用

### 4.3 形态 C：链接

1. **域名分类**（`product_signal.py` 已含白名单）：
   - 电商：淘宝/天猫（tb.cn）、京东（jd.com）、拼多多（yangkeduo/pdd）、1688、闲鱼、抖音、快手、有赞
   - 非电商：公众号文章（mp.weixin）、小程序、其他
2. **商品 ID 提取**：按平台规则解析 URL（如 taobao `id=`、jd `sku`/`100012043978`、pdd `goods_id`）
3. **详情抓取**：复用项目已有 1688/淘宝 adapter 的采集能力补采商品详情（标题/价格/图）；京东/拼多多/闲鱼走对应可执行指南（`adapters/1688/README.md`、`adapters/taobao/README.md`）
4. **结构化**：详情字段 + 来源上下文（哪个群谁发的）合并写入

### 4.4 形态 D：混合

合并规则：
- 文字描述为主，图片补充（多台/铭牌细节），链接补充（商品详情/购买页）
- 合并后统一走 4.1 步骤 2 的 AI 结构化；图片按 4.2 处理
- 字段来源标注：`text|image_ocr|link`，便于追溯与冲突仲裁

## 5. 数据结构与存储设计

### 5.1 表设计（staging 扩展，DDL 随实现提交）

```text
wechat_signal            线索主表（已有）：消息/朋友圈 → 候选 + 群权重 + 形态标签
wechat_product_offer      商品条目（核心）：确认的设备/货源信息
wechat_product_requirement 求购条目
wechat_product_image      图片资产：消息引用 + 图片文件路径 + OCR 文本 + 多模态结果
wechat_product_link       链接解析：URL + 平台 + 商品ID + 详情快照
wechat_product_compare    跨源比对：微信线索 ↔ L2 商品（价格差/同源/新增）
```

### 5.2 商品条目字段规范（对齐 `docs/数据字段规范.md` 风格）

```json
{
  "offer_id": "wx_20260811_001",
  "source_group": "示例货源群（真实群名不入文档）",
  "source_group_weight": 3,
  "source_type": "msg|moment",
  "source_ref": "xxxx@chatroom:1024",
  "create_time": 1786360000,
  "intent": "sell|buy|info",
  "devices": [
    {"name": "娃娃机", "category": "A01", "model": "新款单钩", "spec": "", "count": 5, "condition": "翻新"}
  ],
  "price": 900,
  "price_unit": "元",
  "price_note": "900/台，5台打包可谈",
  "seller": "张三(wxid_xxx)",
  "contact": "13800138000",
  "location": "广州",
  "evidence": {"text": "...", "image": "images/.../a.jpg", "link": "..."},
  "confidence": 0.92,
  "status": "pending|confirmed|rejected|dedup"
}
```

### 5.3 关联设计

- 群权重（`config/group_weights.json`）：S/A/B/C 四级 → 预筛加权、AI 上下文、展示排序、报表聚焦
- 跨源比对：`devices[].name + category` 与 L2 商品库匹配 → 价格差、新增货源、同源去重
- 幂等：`source_ref`（chat+local_id / moment_id）UNIQUE

## 6. 质量与去重

- 规则/AI 双轨冲突 → `field_conflict` 人工队列
- 同源去重：同一群同一设备重复报价 → 按时间/价格变化折叠
- 跨源去重：微信线索与已采商品同 ID（链接）→ 合并
- 人工确认：`status` 工作流（pending → confirmed/rejected），n8n 可挂人工节点

## 7. 安全与合规

- 全程只读微信数据；不写微信任何文件；不 hook、不重启
- 上级账号数据为敏感资产：仅本地 `runtime/`（gitignored），不外发、不展示原始内容
- 群聊含第三方信息，仅用于本项目授权分析
