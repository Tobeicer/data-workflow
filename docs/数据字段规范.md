# 游艺圈数据字段规范（唯一字段契约）

更新日期：2026-08-05

定位：数据侧**唯一字段契约**，合并替代历史 `游艺圈数据导入字段规范_v2.md` 与 `数据库字段基准.md`。定义三件事：

1. **采集全量字段**：以 1688 实际采集证据为准（2026-08-07 重采批次，`deliveries/1688/1688_20260807/`），数据侧**全量拿到信息**。
2. **数据库入库映射**：现有 PostgreSQL `public` schema 真实表结构（`192.168.1.98:5432`），只映射数据库现有列。
3. **字段值规则**：空值、地区、价格、图片、缺失原因的写法。

平台最终页面渲染/展示什么、展示哪些列，**不归数据侧管**；数据侧只保证字段全量采集、可追溯、按映射入库。渲染层可以隐藏缺失字段，但 L0-L2 不能删除原值、证据、缺失原因和历史变化。

## 1. 数据侧字段职责

- 全量保存来源字段、原值、证据（来源 URL、采集时间、页面路径）和历史变化，不因平台表字段缺失而裁剪 L0-L2。
- 入库只映射数据库现有列；数据库未落地的字段（成立年份、厂房面积、资质认证、服务能力、专利、证书、工厂产能等）继续保存在 L1-L2，等待平台扩展列或正式契约。
- 数据侧唯一直接写入点是 `staging_manufacturer` 接收区；`product`、`accessory`、`manufacturer`、`category`、`document` 由平台校验后写入。
- 数据库连接参数只存根目录 `.env.local`（未跟踪）；本文档不存放密码、Cookie 或真实业务数据。

### 2.3 SKU 字段（8 个）

`source_platform`、`offer_id`、`sku_name`、`sku_price`、`stock_text`、`stock_quantity`、`sku_image_url`、`collected_at`

### 2.5 关系与证据

- 商品—店铺、商品—公司、店铺—公司关系带来源页面、采集时间、匹配方法、置信度和冲突原因。
- 店铺名、供应商名和证照主体名不得互相覆盖；跨平台疑似同一公司只建立候选关系。
- 每条字段证据（`field_evidence`）含字段、值、原值、单位、来源 URL、页面路径、原始标签、规范化状态和采集时间。

### 3.3 `accessory`（12 列，正式表，只作参考）

与 `product` 基本一致（`manufacturer_id`、`name`、`category`、`model`、`price_range`、`image_url`、`description`、`status` + 时间字段），无 `category_id`。配件分类白名单见第 4.5 节。**目前无 `staging_accessory` 表**，同上处理。

### 3.4 `category`（6 列）与 `document`（14 列）

- `category`：`id`、`parent_id`、`name`、`sort_order` + 时间字段。分类树维护归平台；数据侧只提供分类候选（来自 `docs/游艺圈游戏游艺设备完整分类清单.md`），不直写。
- `document`：`title`、`type`、`category`、`related_product`、`source`、`source_url`、`summary`、`status`、`attachment_url`、`attachment_file_id`、`attachment_name` + 时间字段。文审资料初版只做 L0-L2 资产与候选交付。

### 3.5 未落地字段（保留 L1-L2，等待平台扩展）

数据库当前没有对应列、但 1688 已采集并必须保留的字段：成立年份、厂房面积 `factory_building_area_sqm`、资质认证明细（`certificates`、`patents`）、服务能力（`processing_methods`、`custom_minimum_order` 等）、工厂产能、年交易额、员工口径、信用指标、坐标与媒体（`factory_images`、`factory_videos`、`factory_vr_url`）等。这些字段继续保存在 L1-L2，平台扩展列或正式契约到达后再映射。

## 4. 字段值规则

### 4.1 空值

空值留空，不写 `NULL`、`无`、`-` 或 `0`。未知数值保持空值；摘要数量与可枚举明细口径不同则分别保存。

### 4.2 缺失原因（L1-L2 必须区分）

来源未提供 `not_provided`、不可访问 `not_accessible`、不适用 `not_applicable`、未请求 `not_requested`、解析失败 `parse_failed`。禁止用空串或 `0` 表达未知。

### 4.3 地区格式

| 情况 | 写法 |
|---|---|
| 三级齐全 | `广东省/广州市/番禺区` |
| 只确认到市 | `广东省/广州市/` |
| 直辖市 | `上海市/上海市/浦东新区` |

省、市不可省略；无法确认省市时进入复核，不写“未知”占位。

### 4.4 价格

- 单一价格：最低价和最高价相同。
- 只有起价：最高价留空。
- 未知价格：两列都留空，不填 0。
- SKU 价格和库存完整保存在 L1/L2；展示层只消费商品级区间。
