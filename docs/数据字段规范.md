# 游艺圈数据字段规范（唯一字段契约）

更新日期：2026-08-14

定位：数据侧**唯一字段契约**，合并替代历史 `游艺圈数据导入字段规范_v2.md` 与 `数据库字段基准.md`。定义三件事：

1. **采集全量字段**：以 1688 实际采集证据为准（2026-08-12 全量重采批次，`deliveries/1688/1688_20260812/`，707 商品 + 4674 SKU），数据侧**全量拿到信息**。
2. **数据库入库映射**：现有 PostgreSQL `public` schema 真实表结构（正式库 `192.168.1.43:5432`，2026-08-14 实测），只映射数据库现有列。
3. **字段值规则**：空值、地区、价格、图片、缺失原因的写法。

平台最终页面渲染/展示什么、展示哪些列，**不归数据侧管**；数据侧只保证字段全量采集、可追溯、按映射入库。渲染层可以隐藏缺失字段，但 L0-L2 不能删除原值、证据、缺失原因和历史变化。

## 1. 数据侧字段职责

- 全量保存来源字段、原值、证据（来源 URL、采集时间、页面路径）和历史变化，不因平台表字段缺失而裁剪 L0-L2。
- 入库只映射数据库现有列；数据库未落地的字段（成立年份、厂房面积、资质认证、服务能力、专利、证书、工厂产能等）继续保存在 L1-L2，等待平台扩展列或正式契约。
- 数据侧直接写入范围（2026-08-14 定案）：`manufacturer`（`import_batch` 批次 + `status='pending'`）与 `industry_source_1688_product`/`industry_source_1688_sku` 接收表（开发期经平台方决定使用 `postgres` 账号）；`product`、`accessory`、`category`、`document` 及其他业务表由平台校验后写入，数据侧不碰。
- 数据库连接参数只存根目录 `.env.local`（未跟踪）；本文档不存放密码、Cookie 或真实业务数据。

### 2.3 SKU 字段与规格结构化（2026-08-14 设计定稿，待实施验证后改库）

L1 每 SKU 记录 13 个字段：`source_platform`、`offer_id`、`sku_name`、`sku_dimension`、`spec_attributes`、`spec_fragments`、`spec_parse_status`、`sku_price`、`sku_price_text`、`stock_text`、`stock_quantity`、`sku_image_url`、`collected_at`。

SKU 是商品下的明细集合，一个商品可有多个 SKU；L1 中按商品保存 `l1/skus.jsonl`。SKU 不能被简化成文本字段，价格/库存/规格需逐 SKU 保存并保留采集时间。交付 Excel `SKU明细` sheet 同步上述字段；商品级价格区间（`price_min`/`price_max` + `price_status`）是同一商品下全部 SKU 价格的聚合，不是商品属性。

**规格结构化三级规则（2026-08-14 定稿）**：

1. 维度声明：`sku_dimension` 记录页面声明的维度名原文（如“颜色”、“规格”、“购买数量”）；多维度时逗号拼接，`sku_dimensions` 数组同步保存。未声明（44/700 实测）标 `not_provided`。
2. 每 SKU 规格值三级抽取：
   - `parsed`：label 内【】括号片段 → `spec_fragments`（证据）→ **右对齐映射**为 `spec_attributes`（`[{"dimension":"颜色","value":"白色"}]`；规格值通常在 label 末尾，左侧括号是型号/套餐前缀，如“33901【超大礼盒】接豆游戏机【黄色】”只取“黄色”）；
   - `label_only`：label 无括号或无法可靠映射（实测 82% SKU）→ `spec_attributes=[]`、`sku_name` 原文保留，平台渲染以 label 文本作选项文案；
   - 括号内多值叠加（如“白色+4电池”）与左侧多余片段 → 标记 `extra_spec_suspected`，**不虚构新维度名**。
3. 铁律：不虚构维度与值；结构化是投影，`sku_name` 原文永远是证据；`spec_parse_status` ∈ `parsed`/`label_only`/`review_required`，解析规则带版本号。

**关系与渲染匹配键**：`source_product` 1—N `source_sku`（`offer_id` 关联不变）；平台“切换规格→价格匹配”的映射键 = `(offer_id, dimension=value…)` 唯一定位 SKU 行 → 取该行价格/库存/图片。建议正式库增加 `sku_option` 规格组表（商品、维度、值、顺序、媒体引用），值从 `spec_attributes` 聚合，`label_only` 商品的值退化为 label 原文。

**实施与库变更顺序（2026-08-14 定案）**：① 解析器与 L1/交付字段落地（不改库）→ ② 全量回溯与人工抽查验证 → ③ 最后改库：`industry_source_1688_sku` 加 `sku_dimension`/`spec_attributes`/`spec_parse_status` 列、product 行补 `sku_dimension`，正式库按建议建 `sku_option`。

### 2.5 关系与证据

- 商品—店铺、商品—公司、店铺—公司关系带来源页面、采集时间、匹配方法、置信度和冲突原因。

## 4. 字段值规则

### 4.1 空值

空值留空，不写 `NULL`、`无`、`-` 或 `0`。未知数值保持空值；摘要数量与可枚举明细口径不同则分别保存。

### 4.2 缺失原因（L1-L2 必须区分）

缺失原因枚举与语义以总纲第 6 节为唯一定义（`not_provided`、`not_accessible`、`not_applicable`、`not_requested`、`parse_failed`、`source_changed`、`conflict`、`unknown` 等）。禁止用空串、`0`、`无` 或 `-` 表达未知。

### 4.3 地区格式

| 情况 | 写法 |
|---|---|
| 三级齐全 | `广东省/广州市/番禺区` |
| 只确认到市 | `广东省/广州市/` |
| 直辖市 | `上海市/上海市/浦东新区` |

省、市不可省略；无法确认省市时进入复核，不写“未知”占位。

### 4.4 价格（2026-08-12 落地实现）

- 交付列：`price_min`/`price_max`（纯数字，元，≤2 位小数）、`currency`（固定 CNY）、`price_status`（single/range/missing/review_required）。
- 单一价格：最低价和最高价相同；只有起价：最高价留空；未知价格：两列都留空，不填 0。
- 价格区间 = SKU 明细价格聚合（页面真实值）；SKU 超高精度原值（如 2.09897095）保留在 `sku_price_text`/L1 `price_text`，交付层规范为 2 位小数。
- SKU 价格和库存完整保存在 L1/L2 与交付 `SKU明细` sheet；展示层只消费商品级区间。
- 页面价格带符号/空格/库存文本（如 `¥14.04库存 874774`）一律在规范化层拆分，禁止原样入库；活动文案节点视为无价格，`price_status=missing`，原文本保留在 L1 `price_text` 作为复核证据。

### 4.5 分类白名单（候选）

主营品类：`游戏设备,管理系统,周边配件,机台销售,产品研发,场地规划,维修服务,二手买卖,合作开店,装修设计,安装调试,其他服务`

配件分类：`币器/投币器,主板/程序板,摇杆按钮,读卡器,屏幕显示,电源线材,支付模块,彩票纸/耗材,礼品机配件,礼品`

资质候选：`CCC认证,CE认证,ISO9001,A级纳税人,高新企业`

服务候选：`来图加工,来样加工,支持打样,可开专票,支持定制,一件代发`

来源平台的“超级工厂、金牌制造、店铺等级、回头率、履约率”等只作为带来源和时间的 L2 信号，不直接转成游艺圈认证等级。

### 4.6 图片

- 不直接交付易失效的外部电商图床链接；转存后提供可公开访问的 HTTPS 地址。
- 建议 JPG/PNG、长边不超过 1000px、单张不超过 500KB。
- 转存失败时留空并进入质量报告，不保留死链。
- 商品主图/轮播图/详情图必须为真实商品图片（http(s)），禁止 SVG、`/tps-` 占位图标；详情内容统一由 `detail_images_json` 承载真实图片 URL，不再单独保留详情内容链接列。
- **原图规则（2026-08-14 定稿）**：NAS 媒体一律存原图，禁止缩略图与转码变体——`x.jpg_sum.jpg`（缩略图）、`x.jpg_400x400.jpg`（尺寸后缀）、`x.310x310.jpg`（尺寸替换扩展名）、`x.jpg_.webp`（webp 变体）统一还原为原图 URL 后再下载。
- **目录归属规则（2026-08-14 定稿）**：每个商品/厂家的媒体文件完整落在自己的目录（`1688/products/<商品ID>/...`），跨实体不共享文件路径——同一图片被多个商品共用时各存一份，平台按目录消费媒体。
